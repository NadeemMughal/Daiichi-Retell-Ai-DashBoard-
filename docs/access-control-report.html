User Roles, Page Access and Permission Audit
Current implementation

1. Access Model

The application has two role systems: platform roles for Daiichi staff and tenant roles for client workspace users. Effective access is the union of applicable roles, then restricted by active profile status, active membership, tenant scope, individual agent grants, server permission checks and Supabase Row-Level Security.

5. Sensitive Data and Security

  • Inactive or suspended profiles cannot use the application.
  • Only active tenant memberships are accepted.
  • Platform roles may be global or tenant-scoped.
  • Tenant-scoped platform roles do not apply to other tenants.
  • An agent can have only one active tenant assignment.
  • Agent grants can be revoked without deleting their history.
  • Calls and chats are tenant-scoped and protected by server checks and RLS.
  • Unauthorized protected routes generally return not-found rather than revealing resource existence.
  • Several administrative mutations write audit-log records.

6. Current Authorization Gaps

  1. Owner and Admin are read-only despite their administrative names.
  2. Billing users have no usable billing page and may receive a not-found dashboard.
  3. No tenant role can open Team because none receives members.read.
  4. Viewer has calls.initiate and chats.respond while senior tenant roles do not.
  5. Permission overrides are stored but not applied by the authorization context.
  6. Owner Dashboard overexposure: after agents.read is accepted, all dashboard views are returned without individual calls/chats/members checks.
  7. Contact management controls may be visible to users whose API action is rejected.
  8. Control Center operational summaries are visible to every platform role.
  9. Tenant recording flags are not applied by the dashboard loader.
  10. contacts.view_unmasked has no implemented workflow.
  11. Some exports are not hidden when reports.export is absent.
  12. Agent Version analytics is unavailable because version is not included in call data.

7. Recommended Priority

  1. Apply page-level permissions to Owner Dashboard.
  2. Hide all unauthorized management controls.
  3. Define meaningful differences for Owner, Admin and Manager.
  4. Create a billing page for Billing users.
  5. Apply membership permission overrides.
  6. Enforce recording, transcript, export and contact-unmasking settings consistently.
  7. Add automated access tests for every role and route.
